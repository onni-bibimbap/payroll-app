# Frontend / PWA — registration app & payroll UI

Facts established during FEAT-005 (2026-09-03, fix agent for FE-01..FE-13, SEC-12, GAP-06 UI).

## Build & styling
- [confirmed] Tailwind is a build-time dependency (v3.4 via PostCSS), configured **inline in `ui/vite.config.js`** — NOT in `tailwind.config.js`/`postcss.config.js` — because `ui/Dockerfile` copies only `package.json`, `index.html`, `vite.config.js`, `public/`, `src/` (source: ui/Dockerfile lines 3–7). Adding root config files silently breaks the Docker build.
- [confirmed] Brand palette lives in that inline config: `brand #1F3864`, `brand-light #2E75B6`, `moss #548235`. The Play CDN script and its `cdn` runtimeCaching entry are gone (FE-02); the SW precaches the hashed CSS asset instead.
- [confirmed] `ui/public/style.css` is a hand-written overlay (print rules, payroll-grid, .seg) loaded via `<link>` — it is separate from the Tailwind pipeline on purpose.

## PWA installability
- [confirmed] `ui/public/icons/icon-192.png` / `icon-512.png` are generated by `ui/scripts/generate_icons.py` (stdlib-only PNG writer; rerun it to regenerate). Manifest declares separate `purpose: any` and `purpose: maskable` entries; glyph sits inside the centre 60% (maskable safe zone). `index.html` carries `apple-touch-icon` + `theme-color`.
- [derived] Service worker + install still require a secure context; TLS termination is the infra agent's scope (FE-11 remainder). HSTS header is present but commented in `ui/nginx.conf` until TLS exists.

## Offline registration queue (Register.jsx)
- [confirmed] IDB keys: `onni-register-draft` (form draft) and `onni-register-queue` (one entry: `{token, form, files, reference_no?, at}`). Document `File` blobs ARE stored in IndexedDB with the queued form (FE-03).
- [confirmed] Flush is single-flight (module-level promise) and token-deduped; a `submission_token` is added to the POST payload — backend `/api/register` accepts a plain dict and persists scalar payload fields into `application_submissions.payload`, so the token lands there as an audit/dedupe anchor (source: backend/app/registration.py ~line 133).
- [confirmed] After the form POST succeeds, `reference_no` is persisted into the queue entry BEFORE doc uploads start; failed docs stay queued keyed to that ref and retry on the next 'online' event. Never re-post a queue entry that has `reference_no`.
- [confirmed] Network failure detection: `err instanceof TypeError` from fetch is treated as offline even when `navigator.onLine` is true (captive portal / backend down) — do not gate queueing on `navigator.onLine` alone (FE-04 hazard).
- [assumed] Cross-restart double-submit window: if the app dies between POST success and the IDB write of `reference_no`, a reopen re-posts; backend `duplicate_suspect` blocker flag is the safety net.

## Payroll run editing
- [confirmed] Slip cell edits are local state until `PUT /api/runs/{id}` recalculates; Submit/Approve now call `saveIfDirty()` first so the locked run always equals the on-screen figures (FE-06). A `beforeunload` guard is active while dirty. There is no react-router blocker because the app uses `<BrowserRouter>` (useBlocker needs a data router) — in-app navigation while dirty is only protected by the visible badge.

## API layer conventions
- [confirmed] `api.js` `money()`/`money0()`: `'-'` ONLY for null/undefined/'' — a genuine 0 renders `0.00` (statutory documents must distinguish "zero" from "n/a", FE-08).
- [confirmed] 401 handling: `setUnauthorizedHandler` in api.js (skips `/api/auth/*`); App clears the user in place so the current URL is preserved and re-renders after re-login. Session-expired flash fires once even with several in-flight 401s.
- [confirmed] All data pages use shared `components/Async.jsx` (`Loading`, `ErrorState retry`) instead of `return null`.

## Route splitting
- [confirmed] All twelve pages are `React.lazy` chunks (FE-09); `/register` loads only index (~174 kB / 57 kB gz) + Register chunk (~15 kB / 5.4 kB gz). The Register chunk is in the SW precache, so the offline form still works.

## GAP-06 UI contract
- [assumed] HRDetail posts `{note}` to `POST /api/hr/employees/{employee_id}/request-resubmission` (backend agent's contract; endpoint did not exist in backend at UI-implementation time). The resulting flag arrives as `flag_type=resubmission_requested`; HRDetail styles it and HRQueue shows a chip when the queue row has `flag_types` containing it (defensive `|| []`, so a queue payload without `flag_types` renders unchanged).

## nginx
- [confirmed] `add_header` is not inherited into locations that declare their own `add_header` — the security header set is deliberately repeated in `location = /sw.js` and `location = /manifest.webmanifest`. Keep that in sync when editing headers.
- [derived] CSP is `default-src 'self'` shaped; `style-src 'unsafe-inline'` is required by React `style={}` attributes (Dashboard bars/segments). No external script/style/font hosts remain after FE-02.
